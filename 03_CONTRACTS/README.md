# Contract Registry

Contracts are the point where architecture becomes implementable.

A contract must answer:

- what the component owns;
- what it consumes;
- what it produces;
- what it may depend on;
- what happens when it fails;
- how it is secured;
- how it can be replaced.

The Bible's component contract template requires 18 fields. These files are the initial contract set.

**Status:** PROPOSED. Phase 0 must harden these before implementation.
